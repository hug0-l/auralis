# Auralis golden corpus

The golden corpus is the reference material the Auralis test-suite uses to
prove that a module still does its job. Every clip is a small, licensed file
with a machine-readable annotation, so a test can say *"the click in this
clip must be at least 20 dB quieter after De-Click"* and check it.

The corpus is **evidence, not a product**: it holds third-party recordings
whose licences are recorded per entry. Nothing here is ever shipped with the
application.

---

## 1. Layout

```
corpus/
  README.md              this file
  manifest.schema.json   JSON Schema of one manifest entry
  manifest.json          the manifest (an array of entries)
  build_corpus.py        the generator: it synthesises every clip
  measure.py             the measurement helper the module tests use
  audio/<split>/<id>.wav  the clips
```

* `manifest.json` is a JSON **array** of entries; each entry is validated
  against `manifest.schema.json`.
* `audio/` is organised by split: `train`, `dev`, `test`. The clips are
  48 kHz, 16-bit or 24-bit PCM WAV, mono unless the annotation says otherwise.
* **Every clip of this corpus is synthesised** by `build_corpus.py`. There is
  no third-party audio in the tree and no attribution file is needed; §4
  states the rules for the day that changes.

---

## 2. Manifest format

One entry describes one clip:

```json
{
  "id": "esc50_000123_click",
  "file": "audio/test/esc50_000123_click.wav",
  "licence": "CC-BY-NC-4.0",
  "source_url": "https://github.com/karoldvl/ESC-50/archive/master.zip",
  "source_credit": "ESC-50 dataset",
  "sample_rate": 44100,
  "channels": 1,
  "duration_s": 5.0,
  "sha256": "9f2c…",
  "split": "test",
  "tags": ["click", "environmental"],
  "annotations": {
    "events": [
      { "type": "click", "start_s": 1.482, "end_s": 1.489, "label": "single click" },
      { "type": "noise", "start_s": 0.0, "end_s": 5.0, "label": "street ambience" }
    ]
  }
}
```

### Field rules

| field | meaning |
|---|---|
| `id` | unique, lowercase, `[a-z0-9_.-]`; the file name stem as well |
| `file` | path relative to `corpus/`, forward slashes, must exist |
| `licence` | SPDX identifier (see the table in §5) |
| `source_url` | the exact page or archive the file was downloaded from |
| `source_credit` | the name to print in the attribution file |
| `sample_rate` | Hz, integer |
| `channels` | integer, 1 or 2 |
| `duration_s` | seconds, float, `> 0` |
| `sha256` | checksum of the file, so a corpus can be verified |
| `split` | `train`, `dev` or `test` |
| `tags` | free-form labels for searching |
| `annotations.events` | the events in the clip, see §3 |

The formal definition lives in [`manifest.schema.json`](manifest.schema.json)
(an entry, not the whole manifest). Validate with any JSON Schema validator,
for example:

```bash
python -c "import json,jsonschema,sys; \
  s=json.load(open('corpus/manifest.schema.json')); \
  [jsonschema.validate(e,s) for e in json.load(open('corpus/manifest.json'))]; \
  print('manifest ok')"
```

## 3. Annotation conventions

* **Times are seconds**, floating point, relative to the first sample of the
  file. `start_s` and `end_s` are absolute positions, not offsets between
  events.
* **Intervals are half open**: `[start_s, end_s)`. An event that starts at
  1.0 s and ends at 1.5 s covers the samples from 1.0 s up to (not including)
  1.5 s.
* `start_s < end_s`, and both must lie inside `[0, duration_s]`.
* **Events may overlap.** A clip with a click inside a hiss has two events
  that overlap in time.
* `type` comes from the controlled vocabulary below. Use the closest match;
  do not invent new types without adding them to this list.
* `label` is a short human-readable description ("single click", "50 Hz hum",
  "female speech"), at most a few words. It is not a key and must not be
  parsed by the tests.
* A clip without any event has `"events": []`.

### Event types

| type | meaning |
|---|---|
| `click` | a single impulsive tick |
| `crackle` | dense impulsive noise (vinyl, rustle) |
| `hum` | mains hum and its harmonics |
| `hiss` | steady high-frequency noise |
| `noise` | general broadband noise |
| `wind` | wind and gusts |
| `rain` | rain |
| `sibilance` | sibilant consonants / sibilant noise |
| `plosive` | plosive consonants (p, b, t) |
| `bleed` | another source bleeding into the recording |
| `reverb` | a reverberant tail or room |
| `clipping` | samples at full scale (distorted) |
| `speech` | intelligible speech |
| `music` | music |
| `silence` | a silent passage |

## 4. Where the audio comes from

**The corpus carries no third-party material at all.**  Every clip is
generated by `corpus/build_corpus.py` from a documented recipe, so:

* the tree holds no audio that was recorded, downloaded or copied by
  anyone,
* the licence question does not arise - the material is generated, and
  every entry records `licence: CC0-1.0`, `source_url: synthesised` and
  `source_credit: synthesised by corpus/build_corpus.py`,
* every clip has an *exactly* known ground truth, and
* a rebuild reproduces every file byte for byte.

The rules below are the ones that apply the day that third-party material
is proposed; they are a policy, not a description of the tree.

1. **Check the licence of the individual file**, not just of the collection.
2. Only material with a permissive, unambiguous licence may enter.
3. Non-commercial licences may be used for research and for the internal
   test corpus, but they must never be redistributed inside a product build
   or in a public release.
4. Record the exact terms in the manifest and keep the files out of any
   distribution.
5. Prefer an official download or a mirror with an explicit licence.  Do not
   scrape a site whose terms forbid it, and do not use a file whose licence
   you cannot state.
6. Every entry that needs an attribution gets a line in
   `corpus/ATTRIBUTION.md`: title, author, licence and source URL.  The
   attribution file is generated from the manifest, never maintained by hand.

A clip whose licence cannot be identified does not enter the corpus.  Nothing
in the corpus may be relicensed, and the corpus may not be redistributed as a
whole outside the project.

## 5. Licensing rules

* `licence` is always an **SPDX identifier**.  The values the corpus accepts:

  | identifier | class | attribution required |
  |---|---|---|
  | `CC0-1.0` | public domain | no |
  | `CC-BY-3.0`, `CC-BY-4.0` | permissive | yes |
  | `CC-BY-SA-4.0` | share alike | yes |
  | `CC-BY-NC-3.0`, `CC-BY-NC-4.0` | non-commercial | yes, research only |
  | `CC-BY-NC-SA-4.0` | non-commercial, share alike | yes, research only |
  | `MIT`, `BSD-3-Clause`, `Apache-2.0`, `Unlicense` | permissive | yes (licence text) |
  | `ITU-T-P.501` | ITU test signals | yes (see §4) |

* **Every clip of this corpus is `CC0-1.0` and synthesised**, so no entry
  needs an attribution line today.
* The manifest is the single source of truth for the licence of a file.  The
  attribution file is generated from it, never maintained by hand.

## 6. Adding a clip

The synthesised set is extended in `corpus/build_corpus.py`:

1. write a recipe that returns a `(entry, samples)` pair - the entry carries
   the ground truth of the clip, the samples are the `(n, channels)` float64
   buffer,
2. record the ground truth: the levels, the frequencies, the positions and
   the durations (§8),
3. add the recipe to `BUILDERS` - the order of the tuple is the order of the
   manifest, and the index of a recipe is part of its seed, so a new recipe
   **appended at the end** leaves the existing clips byte for byte unchanged,
4. run `python corpus/build_corpus.py` and `python corpus/measure.py --verify`,
5. run `python -m pytest tests/test_corpus.py -q`: the gate checks that the
   clip is there, that it matches its manifest, that a rebuild reproduces it
   and that the corpus carries no third-party material.

Short clips (2-10 s) are preferred: the corpus is meant to be small, and the
tests measure a specific moment in the file.

---

## 7. How the corpus is used

* A golden case is `(entry, event, module, expectation)`: *"De-Click must
  attenuate the `click` event of `esc50_000123_click` by at least 20 dB"*.
* The tests read the manifest, pick the entries they need and measure the
  before/after level inside the annotated interval only.
* The corpus is a **gate**: `tests/test_corpus.py` checks that every clip
  matches its manifest, that every claim the manifest makes is the one a
  measurement returns, and that a rebuild reproduces every file byte for
  byte.  A clip that does not match its manifest fails the suite.
* A clip that is not on disk is a skipped test, never a failure.

The synthetic signals in `tests/conftest.py` (white noise, tones, clicks,
hum, clipping, sibilance) cover the numeric cases. The corpus covers the
cases with a known ground truth: the position of every impulse, the level of
every part, the frequency of every partial, the phase between the channels.

## 8. The synthesised golden set

The clips that are in the corpus right now are **synthesised**, not
downloaded. `corpus/build_corpus.py` generates them from documented
recipes, so the repository carries no third-party audio at all, the
licence question does not arise, and every clip has an *exactly* known
ground truth: the position and the amplitude of every impulse, the level
of every tone, the noise floor, the reverberation time, the samples that
sit at full scale.

A synthesised clip has

* `licence`: `CC0-1.0` (the material is generated, not copied),
* `source_url`: the literal string `synthesised`,
* `source_credit`: `synthesised by corpus/build_corpus.py`.

### 8.1 Building and checking

```bash
python corpus/build_corpus.py           # write the clips and manifest.json
python corpus/build_corpus.py --check   # only check that the clips are there
python corpus/measure.py --list         # list the clips of the manifest
python corpus/measure.py --clip clicks  # measure one clip
python corpus/measure.py --verify       # measure everything and check the manifest
python -m pytest tests/test_corpus.py -q   # the gate around the corpus
```

The generator is deterministic: it uses the fixed seed `20260201` and
nothing else that could change between two runs, so two runs produce
byte-identical files (compare the `sha256` field of the manifest).
`--verify` re-measures every clip with `corpus/measure.py` and compares
every figure with the ground truth of the manifest; it prints one line per
check and the number of checks at the end.  It is the acceptance test of
the corpus, and `tests/test_corpus.py` is the gate around it (§8.19).

### 8.2 Format and the normalisation rule

| property | value |
|---|---|
| sample rate | 48 000 Hz |
| channels | 2 - identical in both channels, except `hiss`/`pink_hiss` (independent noise), the mid/side pair and `voice_hiss` (the voice is common, the hiss is independent) |
| bit depth | 24-bit PCM, little endian |
| length | 2.0 s (`clicks.wav` is 3.0 s) |
| licence | `CC0-1.0` |
| source | `synthesised` |

Every clip is mixed from its components and then scaled **once**, with the
same rule for every clip:

* `clicks.wav` and `clipped.wav` are scaled so that their peak is
  0 dBFS - the full-scale click and the hard clip define it;
* the tone clips are scaled so that their peak is -6 dBFS;
* the noise clips are scaled so that the RMS of *every channel* is
  -60 dBFS.

The gain that was applied is recorded in the manifest
(`annotations.levels.normalisation_gain`), so the level of every
component in the file can be recomputed from the recipe.  The component
levels in the manifest are the levels **in the file**, after that gain.

Two conventions that the tables below use:

* a **band level** (`annotations.bands`) is the share of the signal's
  power that lies in the band, in dBFS.  A full scale sine inside the
  band therefore reads -3.01 dBFS (its RMS, not its peak) and the value
  of a tone is always 3.01 dB below its peak amplitude;
* a **true peak** is the inter-sample peak (4x oversampling).  It equals
  the sample peak for a tone and for a single-sample impulse, and it is
  slightly *higher* for a clipped waveform, whose corners overshoot
  between the samples (`clipped.wav` reads +0.18 dBTP).

### 8.3 `clicks.wav` - the impulse clip (3.0 s)

A 480 Hz tone bed at -40 dBFS with **six single-sample impulses** at
0.5 s intervals:

| time | sample | amplitude | above the bed |
|---|---|---|---|
| 0.250000 s | 12000 | 0.00 dBFS (full scale) | 43 dB |
| 0.750000 s | 36000 | -4.00 dBFS | 39 dB |
| 1.250000 s | 60000 | -8.00 dBFS | 35 dB |
| 1.750000 s | 84000 | -12.00 dBFS | 31 dB |
| 2.250000 s | 108000 | -16.00 dBFS | 27 dB |
| 2.750000 s | 132000 | -20.00 dBFS | 23 dB |

480 Hz has exactly 100 samples per period at 48 kHz and every click
position is a multiple of 12000 samples, so every click sits on a zero
crossing of the bed: the impulse is *added* to a bed sample that is
zero and the value of the click sample is exactly the amplitude above.

Measured: peak 0.00 dBFS, RMS -42.11 dBFS, true peak 0.00 dBTP, the bed
in the 450-510 Hz band -43.01 dBFS.  The full-scale click is one sample
at full scale, so the clip has exactly **1** sample at or above 0.999.

`measure.detect_clicks` finds the six impulses at exactly the positions
and the levels of the table, and nothing else.

Used by: De-Click, Mouth De-Click, De-Crackle, De-Plosive, Spectral
Repair.

### 8.4 `hum50.wav` - the mains hum clip (2.0 s)

A 1 kHz reference tone with a 50 Hz hum and its 100 Hz harmonic:

| component | frequency | peak | band | band level |
|---|---|---|---|---|
| tone | 1000 Hz | -7.63 dBFS | 950-1050 Hz | -10.64 dBFS |
| hum | 50 Hz | -23.63 dBFS | 45-55 Hz | -26.64 dBFS |
| harmonic | 100 Hz | -29.63 dBFS | 95-105 Hz | -32.64 dBFS |

The hum is 16 dB below the tone, the harmonic 22 dB below the tone and
6 dB below the hum.  Measured: peak -6.00 dBFS, RMS -10.50 dBFS.

Used by: De-Hum.

### 8.5 `hiss.wav` and `pink_hiss.wav` - the noise clips (2.0 s)

White noise and pink noise (power density proportional to 1/f), both at
**-60.00 dBFS RMS per channel**, independent in the two channels.

| | `hiss` | `pink_hiss` |
|---|---|---|
| peak | -46.78 dBFS | -47.47 dBFS |
| RMS of the mono mix | -63.04 dBFS | -63.49 dBFS |
| broadband 20 Hz - 20 kHz | -63.83 dBFS | -65.18 dBFS |
| low 20 Hz - 250 Hz | -83.22 dBFS | -69.72 dBFS |
| high 5 kHz - 20 kHz | -65.10 dBFS | -72.11 dBFS |

The pink clip has 13.5 dB more energy in the low band and 7 dB less in
the high band - the -3 dB/octave tilt.  The mono mix of two uncorrelated
channels is 3 dB below the level of one channel; that is why the mono
mix RMS reads -63 dBFS while the noise itself is at -60 dBFS.

Used by: Voice De-Noise, Spectral De-Noise, Noise Reduction, the
spectral repair and recovery modules.

### 8.6 `sibilance.wav` - the sibilance clip (2.0 s)

A 1 kHz tone (peak -14.96 dBFS, 950-1050 Hz band -18.13 dBFS) with a
**6 kHz sibilance burst** from 0.600 s to 0.900 s: band limited noise
between 5 kHz and 7 kHz with a raised-cosine envelope, peak -6.96 dBFS,
the 5-7 kHz band over the burst -22.06 dBFS.  Measured: peak -6.00 dBFS,
RMS -17.80 dBFS.

Used by: De-Ess, Spectral De-Noise.

### 8.7 `plosive.wav` - the plosive clip (2.0 s)

A vowel-like tone (fundamental 120 Hz, 24 harmonics, formants at 700,
1200 and 2600 Hz, peak -16.09 dBFS, 60-3000 Hz band -25.83 dBFS) with a
**low-frequency burst** from 0.500 s to 0.540 s: an exponentially
decaying 80 Hz sine (tau = 8 ms) plus noise below 300 Hz.  The burst
peaks at -6.09 dBFS; the 40-100 Hz band of the whole clip is -35.86 dBFS.
Measured: peak -6.00 dBFS, RMS -25.63 dBFS.  The detector finds exactly
one transient, at 0.5026 s.

Used by: De-Plosive, Mouth De-Click.

### 8.8 `reverb.wav` - the reverberation clip (2.0 s)

A 5 ms 440 Hz starter at 0.200 s convolved with a synthesised impulse
response of 1.5 s: a direct sound plus noise with an exponential decay
of `tau = RT60 / ln(1000) = 0.173718 s`, so the reverberation time of
the room is **exactly 1.2 s**.  The tail starts at 0.205 s.

The reverberation time is measured in the window **0.35 s - 1.75 s**
(`annotations.regions.rt60`): `measure.rt60` returns **1.20 s** there
(Schroeder T30).  The 410-470 Hz band of the whole clip is -40.03 dBFS;
the starter itself is at -6.00 dBFS peak.

The starter is deliberately short: the envelope of a narrow band decay
fluctuates over the length of the excitation, and a long starter would
make the reverberation time unreadable.

Used by: De-Reverb, Spectral De-Noise, the leveler and the loudness
modules.

### 8.9 `clipped.wav` - the clipping clip (2.0 s)

A 1 kHz sine driven to **twice full scale** and hard clipped at +-1.0.
**68000 of the 96000 samples (70.8 %) sit at full scale**, in 4000 runs
(two per period of the tone).  The first runs are listed in
`annotations.positions`.  Measured: peak 0.00 dBFS, RMS -1.05 dBFS,
true peak +0.18 dBTP, the 950-1050 Hz band -1.29 dBFS.

Used by: De-Clip, Clip Classifier, the leveler and the loudness
optimiser.

### 8.10 `silence.wav` - the silence clip (2.0 s)

Digital silence: every sample is zero.  Peak, RMS and true peak all read
-120 dBFS (the floor of the analyser).

Used by: the normalisation, the dither, the leveler and the "is there
anything here" paths.

### 8.11 `stereo_mid.wav` and `stereo_side.wav` - the channel clips (2.0 s)

With `mid = (L + R) / 2` and `side = (L - R) / 2`:

* `stereo_mid.wav`: `L = R` = a 440 Hz tone at -6.00 dBFS.  The **mid**
  carries the tone (410-470 Hz band -9.01 dBFS), the **side is digital
  silence** (-120 dBFS).  The inter-channel correlation is +1.
* `stereo_side.wav`: `L = -R`, a 220 Hz tone at -6.00 dBFS.  The **side**
  carries the tone (200-240 Hz band -9.01 dBFS), the **mid is digital
  silence** (-120 dBFS) and the mono mix is silent.  The inter-channel
  correlation is -1.

Used by: Center Extract, Azimuth, Mixing, Phase, the width and the
channel-operations modules.

### 8.12 `voice_hiss.wav` - the voice with a hiss (2.0 s)

A vowel-like voice (fundamental **130 Hz**, 30 harmonics, the formants of
`/a/`) and a hiss underneath it.  The voice is **identical in the two
channels** and the hiss is **independent**, so the two components sit in
different parts of the stereo image and both levels are exact:

| component | where it is | level in the file |
|---|---|---|
| voice | the **mid** | -17.89 dBFS RMS |
| hiss | the **side** | -34.60 dBFS RMS |
| signal-to-noise ratio | mid RMS minus side RMS | **16.71 dB** |

The side signal is the difference of two independent noise fields divided by
two, so its RMS is the RMS of one channel over the square root of two: the
per-channel noise is at -31.59 dBFS.  Measured: peak -6.00 dBFS, RMS
-17.80 dBFS, the 100-4000 Hz band of the mid -17.87 dBFS, the 5-20 kHz band
of the side -36.64 dBFS, the fundamental at 130 Hz.

Used by: Voice De-Noise, Spectral De-Noise, Noise Reduction, the de-esser
and the leveler.

### 8.13 `music_mix.wav` - the music mixture (2.0 s)

Three musical parts at once: a **bass line** (110 Hz), a **triad**
(220 / 330 / 440 Hz) and a **kick drum** (a 70 Hz burst with a 25 ms
decay) that hits twice.

| part | frequency | level in the file | where |
|---|---|---|---|
| bass | 110 Hz | -29.89 dBFS | the whole clip |
| triad | 220 / 330 / 440 Hz | -27.89 dBFS | the whole clip |
| kick | 70 Hz | -7.89 dBFS | 0.300 s and 1.100 s |

The two drum hits are the only transients of the clip: the parts start at a
zero crossing, so the mixture begins without a step.  Measured: peak -6.00
dBFS, RMS -23.88 dBFS, the 55-85 Hz band over the first hit -26.68 dBFS
(more than 6 dB louder than outside the hit), the 100-120 Hz band
-32.27 dBFS, the 200-500 Hz band -26.31 dBFS.

Used by: Music Rebalance, Deconstruct, Dialogue Isolate, the leveler and
the loudness modules.

### 8.14 `stereo_phase.wav` - the phase pair (2.0 s)

Both channels carry the same 440 Hz tone at -6.00 dBFS, the right one a
**quarter of a period (90 degrees) later**.  The ground truth of the
relation between the channels is in `annotations.phase`:

| figure | declared | measured |
|---|---|---|
| phase of the right channel | +90.00 degrees | +90.00 degrees |
| inter-channel correlation | 0.000 | 0.000 |

The mid and the side carry the same level (-9.01 dBFS peak, -12.02 dBFS in
the 410-470 Hz band): two tones a quarter period apart add up to the same
in both.  The mono mix is therefore 3 dB below the channels.

Used by: Phase, Stereo Width, Azimuth, Center Extract, Mixing, Ambience
Match.

### 8.15 `rumble.wav` - the low level rumble (2.0 s)

A 1 kHz programme tone with **handling noise** under it: a 40 Hz sine at
-29.55 dBFS and band limited noise between 20 Hz and 80 Hz at -35.55 dBFS.

| band | level in the file |
|---|---|
| 20-80 Hz (the rumble) | -30.36 dBFS |
| 950-1050 Hz (the programme) | -10.56 dBFS |

The rumble is **19.81 dB below the programme** - the difference of the two
band levels, which is the figure in `annotations.derived`.  Measured: peak
-6.00 dBFS, RMS -10.51 dBFS, the rumble partial at 40 Hz.

Used by: the high-pass and rumble filters, De-Hum, Spectral De-Noise, the
leveler and the "is there anything here" paths.

### 8.16 `pitch_drift.wav` - the drifting pitch (2.0 s)

A tone whose pitch drifts slowly upwards: **440 Hz** for the first 0.4 s, a
linear glide to **480 Hz** over the next 1.2 s (33.33 Hz/s) and 480 Hz for
the rest.  The phase is continuous, so the glide has no click.

| window | frequency | how it is measured |
|---|---|---|
| 0.000 - 0.400 s | 440 Hz | the strongest partial, +-3 Hz |
| 1.600 - 2.000 s | 480 Hz | the strongest partial, +-3 Hz |

Measured: peak -6.00 dBFS, RMS -9.01 dBFS.

Used by: Time & Pitch, Variable Pitch, Wow & Flutter, the drift and the
pitch-tracking modules.

### 8.17 Measuring a clip - the API of `corpus/measure.py`

`corpus/measure.py` is the helper the module test-suites use.  It needs
`numpy` only and imports nothing from `aurcore`:

```python
from corpus import measure            # or:
import sys; sys.path.insert(0, "corpus"); import measure

# the corpus
measure.load_manifest()                   -> list[dict]      # the manifest
measure.manifest_entry("clicks")          -> dict            # one entry
measure.clip_path("clicks")               -> pathlib.Path
measure.load_clip("clicks")               -> (samples, sr)   # (n, ch) float64

# the measurements
measure.measure_clip("clicks")            -> dict            # everything at once
measure.measure(samples, sr)              -> dict

measure.band_energy_db(x, sr, lo, hi, start=None, end=None, mix="mono") -> float
measure.band_levels_db(x, sr, bands=None, start=None, end=None, mix="mono") -> dict
measure.detect_clicks(x, sr, threshold_db=20.0, floor_dbfs=-40.0,
                      min_gap_s=0.005, block_ms=200.0)          -> list[dict]
measure.clip_runs(x, threshold=0.999, mix="ch0")                 -> list[tuple[int, int]]
measure.clip_stats(x, threshold=0.999, mix="ch0")                -> dict
measure.rt60(x, sr, start=None, end=None, method="schroeder")    -> float | None
measure.peak_db(x) / measure.true_peak_db(x) / measure.rms_db(x) -> float
measure.mid_side(x)                                              -> (mid, side)
measure.mix_signal(x, "mono" | "mid" | "side" | "left" | "right") -> np.ndarray

# the frequency, the phase and the correlation
measure.dominant_frequency(x, sr, start=None, end=None, mix="mono",
                           low_hz=20.0, high_hz=20000.0)          -> float | None
measure.spectral_centroid_hz(x, sr, start=None, end=None, mix="mono",
                             low_hz=20.0, high_hz=20000.0)        -> float
measure.phase_difference_deg(x, sr, start=None, end=None)        -> float | None
measure.interchannel_correlation(x, sr, start=None, end=None)    -> float
measure.pitch_track(x, sr, window_s=0.25, hop_s=0.25)            -> list[dict]

# the ground truth of the manifest
measure.ground_truth_claims(entry)                               -> list[dict]
measure.ground_truth_count(entry)                                -> int
measure.verify_corpus(tolerance_db=0.3, manifest=None, audio_dir=None)
                                                                 -> {"ok", "clips", "checks", "failed"}
```

`measure()` returns one dictionary with

| key | meaning |
|---|---|
| `sample_rate`, `channels`, `frames`, `duration_s` | the shape of the signal |
| `peak_db` | the largest sample of the whole buffer |
| `true_peak_db` | the inter-sample peak (4x oversampling) |
| `rms_db` | the RMS of the mix; `rms_ch_db` holds the RMS of every channel |
| `bands` | the level of every band of `CORPUS_BANDS` (or `OCTAVE_BANDS`) |
| `clicks` | the detected transients: `index`, `time_s`, `peak`, `peak_dbfs`, `excess_db`, `width_s` |
| `clip` | `runs`, `run_count`, `clipped_samples`, `clipped_fraction`, `clipped_seconds` |
| `rt60_s` | the reverberation time, `None` when the signal does not decay |

How the numbers are produced:

* **band level** - the share of the power of the signal that lies in the
  band.  The window limits the resolution: a band narrower than
  `4 * sample_rate / length` of the selection is only measured partially,
  so a narrow band needs a long window.
* **click detector** - the background is the *median* power over 200 ms
  (a transient is far too short to move a median); a sample that is 20 dB
  above the background and louder than -40 dBFS is a candidate, and
  neighbouring candidates form one transient.
* **reverberation time** - the Schroeder T30 by default; `method="energy"`
  uses the decay of the analytic envelope instead.
* **true peak** - 4x oversampling with a band-limited interpolating
  kernel.  The figures agree with `aurcore.dsp.loudness.true_peak_linear`
  to 1e-16.
* **dominant frequency** - the spectrum of the selection with a Hann window,
  zero padded to four times its length; the strongest bin inside the search
  band, refined by a parabolic interpolation of the log of the magnitude.
  The search band is what makes a harmonic measurable without the
  fundamental disturbing it.
* **spectral centroid** - the centre of mass of the power spectrum.  White
  noise sits at the middle of the band, pink noise well below it.
* **phase difference** - the analytic signal of the two channels; the phase
  of the weighted cross product of the two.  `+90` means that the right
  channel leads the left one by a quarter of a period.

A test that wants the ground truth of a clip reads it from the manifest
and compares it with the measurement of the same clip:

```python
entry = measure.manifest_entry("hum50")
truth = {band["name"]: band for band in entry["annotations"]["bands"]}
samples, sr = measure.load_clip("hum50")
measured = measure.band_energy_db(samples, sr, 45.0, 55.0)
assert abs(measured - truth["hum"]["level_dbfs"]) < 0.3
```

### 8.18 The ground truth a clip carries

Every clip of the manifest states its ground truth in a form a test can
assert.  The blocks of `annotations`:

| block | what it holds | how it is checked |
|---|---|---|
| `levels` | the levels in dBFS: the peak, the RMS, the total RMS, the noise floor, the level of every part, the gain that was applied | `peak_dbfs`, `rms_dbfs`, `total_rms_dbfs`, `noise_floor_dbfs`, `mid_peak_dbfs`, `side_peak_dbfs`, `mid_rms_dbfs`, `side_rms_dbfs` and `hiss_rms_dbfs` are **measured**; the other keys are the recipe of the clip and are checked by a rebuild |
| `events` | the events of the clip, with their window | the window has to lie inside the clip, a `click` has to be a transient that the detector finds where the manifest says it is, and no other transient may be there |
| `positions` | the runs of samples that sit at full scale | every run has to be where the manifest says it is |
| `regions` | the named measurement windows | the window has to lie inside the clip |
| `bands` | the level of every frequency band, with the band edges, the window and the signal | the band is measured and compared; a band with a `min_excess_db` has to be louder inside its window than outside it |
| `frequencies` | the frequency of every partial: the name, the frequency, the window, the search band and the tolerance | the strongest partial of the search band is measured and compared; a `null` frequency means the clip holds no partial |
| `phase` | the phase of the right channel relative to the left one and the correlation of the two | both are measured and compared |
| `derived` | a figure that is the difference of two measured ones (the signal-to-noise ratio of the voice clip, the distance between two band levels) | the terms are measured and added up |

`measure.ground_truth_claims(entry)` returns the claims of an entry as a
flat list, `measure.ground_truth_count(entry)` their number.

### 8.19 The gate

The corpus is not a pile of files, it is the instrument the module tests
measure with, so it is checked:

```bash
python corpus/measure.py --verify     # every claim of every clip
python -m pytest tests/test_corpus.py -q
```

`measure.py --verify` measures every clip and compares **every** claim the
manifest makes: the file and its checksum, the sample rate, the channel
count, the duration, the levels, the derived figures, the bands, the
frequencies, the phase, the reverberation time, the positions of the
transients and the runs of clipped samples.  It prints one line per check
and the number of checks at the end.

`tests/test_corpus.py` is the gate around it.  It checks that the manifest
matches its schema, that every clip is on disk with the recorded checksum,
that every clip carries assertable ground truth, that the material the
module owners need is there, that a rebuild reproduces every file byte for
byte, and - the point of the whole thing - that **a clip which does not
match its manifest fails**: the test copies the corpus into a temporary
directory, turns a clip up by 1.5, removes another one, moves a click and
rewrites a claim in the manifest, and asserts that the verification reports
the failure in every case.  The corpus itself is never written to by the
tests.

### 8.20 What this section changes in the sections above

* §1 said the clips are mono unless the annotation says otherwise.  The
  synthesised set is **stereo** (the manifest records `channels: 2`),
  because the mid/side clips need two channels and the channel-operations
  modules are tested with them.
* The `source_url` of a synthesised clip is the literal string
  `synthesised`; `manifest.schema.json` was extended to accept it, and
  its `format: uri` was dropped because the string is not a URI.
* The schema was extended - **additively**, every entry that validated
  before still validates - with the ground truth of the synthesised
  clips: `annotations.levels`, `annotations.positions`,
  `annotations.regions`, `annotations.bands`, `annotations.mix` and the
  optional `amplitude_dbfs`, `center_hz` and `band_hz` of an event, and
  later with `annotations.frequencies`, `annotations.phase`,
  `annotations.derived` and the `min_excess_db` of a band.
* `clicks.wav` is 3.0 s long: six impulses at 0.5 s intervals do not fit
  into two seconds.
* §7 said the synthetic signals live in `tests/conftest.py`.  They still
  do - the synthesised corpus clips are the *golden* material, and
  `corpus/measure.py` is the measurement helper the module tests use to
  read them.
* §4 and §5 described third-party sources.  The corpus carries none: every
  clip is synthesised and `CC0-1.0`, and the rules there are now the policy
  for the day that changes.
